项目分四个里程碑交付。M1、M2 属于 v1 范围；M3、M4 为已确认方向的预留功能，先保留文档与设计语义，暂不实现。

## 设计阶段结论

设计树已通过多轮问答闭合（除"待确认清单"中的非阻塞项外）。本文件与 CONTEXT.md、docs/adr/ 共同构成开发依据：后续任何开发、讨论、迭代都以这些文档为准，不依赖历史对话。M1 范围已冻结，待用户下达开始指令后动工。

## M1 提示词工作区（范围已冻结）

- 卡片分类管理：分类新建/重命名/删除（删除前确认，卡片进回收站）；卡片按名称排序 + 搜索过滤。
- 卡片交互：悬停展开预览（提示词预览 + 添加/修改按钮）、点击进入详情弹窗（完整提示词、预留演示图片位、添加/修改）、不同分类小角标样式、流畅动画（3D 倾斜、Q弹出现）。
- 块式工作区：正面/负面两个区域（随时切换，一次只编辑一个，卡片添加到当前区域，两区分别自动保存）；块 = 卡片引用（实时关联，复制时展开）+ 自由文本块；粘贴自动分块（可开关）+ 手动拆分；拖拽排序；悬停高亮；块上小叉删除；撤销/重做（Ctrl+Z/Y）；一键清空工作区（确认后执行）。
- 复制（导出）：块间 ", " 连接、卡片引用展开、卡片内部换行保留、输出规范化；卡片内容支持嵌套引用 `<分类:名称>` 与循环检测。
- 导入导出：内置 xlsx 模板（分类/名称/提示词/图片可选，模板见 `templates/`）、导出整个库为 zip；配使用说明与模板文件。
- 主题与设置：明暗模式、主色、圆角/玻璃强度、自定义 CSS 注入；设置页含库路径、规范化开关等。
- 一键启动：`run.bat`（Windows）/ `run.sh`（macOS），仅需 Python 3.10+；后端托管前端构建产物。

### M1 后端 API 清单

- `GET/POST/PUT/DELETE /api/categories` — 分类 CRUD
- `GET /api/cards`（按分类/搜索）、`GET/POST/PUT/DELETE /api/cards/{id}` — 卡片 CRUD
- `POST /api/cards/import`（xlsx 模板）、`GET /api/cards/import-template`（下载模板）、`GET /api/cards/export`（zip）
- `GET/PUT /api/workspace` — 工作区两个区域的块列表持久化
- `GET/PUT /api/settings` — 设置

### M1 验收标准

- 新建卡片保存后，对应分类列表立即出现，无需任何刷新。
- 修改卡片：只有点"保存"才真正落盘，"取消"丢弃修改。
- 工作区：添加/删除/拖拽/高亮/撤销/重做/一键清空全部可用，重启后状态还原。
- 复制输出符合规范格式（英文逗号分隔、无多余空格、嵌套引用已展开）。
- xlsx 模板导入与 zip 导出可用。
- 主题切换即时生效。

## M2 图片库（v1，紧接 M1）

- 瀑布流：`react-hybrid-masonry`（虚拟滚动），封装为可替换的 Gallery 组件。
- 放大查看：`yet-another-react-lightbox`；放大后需手动点击"读取 PNG 信息"才解析，完整 JSON 显示在详情面板（参考 ANR 法术解析的实现）。
- 详情面板："发送到工作区"将正面/负面提示词整体覆盖到工作区两个区域（执行前提示覆盖）。
- 浏览方式：先选择大分类（全部 / Treasure / Fine / Reject / 收藏 / 未评分），进入大分类后才按日期分组展示，日期间有分割线。
- 筛选模式：一次放大一张图，Treasure / Fine / Reject / Like（键盘 ← ↓ → ↑）；只打临时标签，结束筛选后统一移动文件（Reject 移入回收站，可配置为永久删除）；会话内撤销；未评分图片保持原位。
- 目录结构：`library/<前缀>/<前缀>-<日期>/图片`（如 `Treasure/Treasure-2026-08-10`）；未评分 = 图库根目录下未进入任何分类的图片（按日期目录 `library/<日期>/`）。

## M3 发布处理（预留）

发布处理有独立的入口与独立的暂存区，完全不影响图库原图：

- 从图库多选图片 → "发布处理"按钮将图片**复制**进发布暂存区的"初始化"文件夹（图库原图原地不动）。
- 发布处理入口内可查看暂存区当前图片；暂存区为空时引导用户去图库勾选加入。
- 处理采用"步骤文件夹"模型：每一步从前一文件夹读入、处理、输出到本步骤文件夹（初始化 → 数据抹除 → 超分降噪），步骤可自选、可跳过。
- 发布完成后清理暂存副本（清理时机待确认：建议"完成发布"确认后清空，或提供手动清空按钮）。
- 批量重命名规则：忽略原名，格式 `{YYMMDD}{6位序号}_{后缀}`，序号从 114514 起 6 位递增，后缀默认 "moni"、可填写（通常是角色名）。示例：`260806114514_moni`。

### 扩展功能 1：批量数据抹除

在发布暂存区内执行：将"初始化"文件夹的图片处理后输出到"数据抹除"文件夹，批量抹除元数据（移除 PNG 元数据，像素不变），效果与 ANR 一致；图库原图完全不受影响。

### 扩展功能 2：超分降噪

对暂存区图片批量超分降噪，输出到"超分降噪"文件夹。引擎采用与 ANR 相同的获取策略：可联网自动下载，也可指定本地路径。

> 待确认：用户提到"只保留一个引擎即可"，并提及 wd-tagger。wd-tagger 属于图片反推（法术解析），与超分引擎（realcugan / Anime4K / waifu2x）不是同一类组件；超分引擎具体保留哪一款、图片反推是否纳入，实现前需确认。

## M4 NovelAI 接入与批量生成（预留）

- 生成参数预设：保存一组生图参数（模型、分辨率、采样器、种子、负面预设等），批量生成时选择预设。
- 卡片组合批量生成：从若干分类各选若干卡片并设定系数（系数 ≥ 1），实时计算总张数（总张数 = 各类 选中卡片数×系数 的连乘），确认后自动组合提示词并调用 NovelAI 生成。停止条件双上限：**剩余点数低于用户设定阈值时终止**（读取剩余点数，参考 ANR 的 `inquire_anlas`）；**可选最大张数上限**（默认 -1 无上限，超过设定值即终止）。
- 职责划分：提示词归卡片（卡片组合），参数归预设（生成参数预设，含模型、分辨率、采样器、种子、负面预设等）。接口调用与请求构造完全参考 ANR 的 `src/generate_images.py` 与 `utils/models/`。

### M4 共识补充（2026-08-07 与用户确认）

- **Token 安全**：NovelAI 持久 token 属敏感凭据，只存于 `config.json`（已 gitignore）/独立本地文件，严禁提交到仓库；代码与文档中不得出现真实 token。
- **接口依据**：以 ANR 开源项目源码为准；后续接口若有变更，参考官方文档 <https://docs.novelai.net/en/image>。
- **免费额度参数**：用户为最高级会员；迭代步数 ≤ 28、分辨率不超过竖版 831×1216 及 3 档更小分辨率、单次仅请求 1 张（`n_samples=1`）时免费。具体参数由前端 UI 配置；测试必须使用用户预设，避免消耗点数。
- **生成输出**：生成图保存到图库未评分目录，并按日期建子文件夹（`library/<日期>/`），沿用现有时间索引；文件名参考 ANR 默认 `<种子>_<随机字符>.png`（10 位种子）；官方出图命名不确定时按 ANR 的处理方式。
- **优先级**：M3 发布处理搁置（视为独立插件，后续单独实现）；M4 先实现文生图（单张 → 参数预设 → 卡片组合批量生成）。
